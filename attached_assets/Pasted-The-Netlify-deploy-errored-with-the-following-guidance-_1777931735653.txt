The Netlify deploy errored, with the following guidance provided:

Diagnosis

- The bundler failed when building your Netlify Function because it could not resolve two runtime modules: pino-http and pino. See the error about pino-http at [line 121](#L121)-[line 125] and the error about pino at [line 126](#L126)-[line 130]. The build summary also repeats these failures at [line 139](#L139)-[line 140](#L140).  
- Netlify reports this as "A Netlify Function failed to require one of its dependencies" and instructs that the dependency must be present in the site's top-level package.json ([line 135](#L135)-[line 137](#L137)).

Cause

- The function bundle attempted to import pino-http and pino but the bundler (esbuild) could not find/install those packages in the build environment. In monorepos or workspace setups the function bundler looks to the top-level package.json for dependencies; if the packages are not listed/installed at the repo root, esbuild fails to resolve them.

Solution

1) Verify packages are listed and committed
- First verify that pino and pino-http are declared in your repo's top-level package.json (not only in a subpackage). Open:
  - https://github.com/xnexgamerx-byte/food-order/blob/main/package.json
- If they are missing, add them to the top-level package.json. If you use npm, run at the repo root:
```bash
# from repo root
npm install pino pino-http --save
git add package.json package-lock.json
git commit -m "chore: add pino and pino-http for Netlify functions"
git push
```
- If you use yarn or pnpm, run the equivalent (yarn add pino pino-http or pnpm add pino pino-http) and commit the lockfile.

2) Re-deploy
- After committing those changes, trigger a new Netlify deploy. Netlify will install the top-level dependencies and the esbuild bundling step should be able to resolve pino and pino-http.

Optional alternative (exclude from bundle)
- If you prefer not to bundle these modules and want the function to require them at runtime, you can mark them as external for Netlify functions. Before doing this, verify the packages are still present in the top-level package.json (see step 1). Then add an external config in netlify.toml:
```toml
[functions]
  external_node_modules = ["pino", "pino-http"]
```
- Commit netlify.toml and redeploy. This tells Netlify not to bundle those modules into the function; they must be installed at runtime (so they still need to be listed in package.json and installed).

Notes
- The import.meta warnings about CJS/ESM ([line 111](#L111)-[line 120]) are warnings and not the cause of the failure; fix them later by ensuring your function output format supports import.meta (e.g., output ESM) if needed.
